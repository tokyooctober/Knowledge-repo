# Knowledge Repository — Master Specification

A personal RAG system that answers natural-language questions about one author's premium
articles, with inline citations generated by Claude.

The database is populated from **two content sources**:

| | Phase 1 — Corpus | Phase 2 — Email |
|---|---|---|
| **What** | The back-catalogue, already exported as markdown + images | Each new report as it is published |
| **Source** | A local folder (`MD_CORPUS_DIR`) | A notification email containing a direct link |
| **Acquisition** | `ingestion/md_loader.py` — read files from disk | `email_reader` → `login` → `crawler` → `extractor` |
| **Cadence** | Re-runnable sync; run it whenever files change | Monthly / every 12h poll |
| **Auth needed** | None | Yes — Playwright login, paywall |

Both phases converge on the same `Article` object and share one ingestion sub-pipeline
(transcribe images → chunk → embed → store). Both are idempotent: re-running either with
unchanged content produces only skips, never duplicate vectors.

> **Changed in this revision.** Phase 1 previously read a `seeds.txt` list of URLs and
> scraped the back-catalogue. It now loads markdown files from disk instead. `seeds.txt`,
> `DEFAULT_SEED_FILE`, and `run_seed()` are gone. Phase 2 is unchanged — the scraper and
> email reader are still fully live, and are the only way new reports enter the system.

## Commands

```bash
# Phase 1 — sync the markdown corpus (re-runnable; new + changed files only)
python scheduler/monthly_job.py --corpus
python scheduler/monthly_job.py --corpus --dry-run          # report, write nothing
python scheduler/monthly_job.py --corpus --dir /path/to/md  # override MD_CORPUS_DIR

# Phase 2 — email-triggered updates
python scheduler/monthly_job.py            # blocking scheduler (APScheduler)
python scheduler/monthly_job.py --once     # single check, then exit (for OS cron)

# Query
streamlit run app.py
python app.py "What are the author's views on monetary policy?"
```

### The one-Article invariant

`md_loader.load_article()` and `extractor.extract()` are the only producers of an
`Article`. Everything downstream is source-agnostic and must stay that way — no module
after the loader may branch on `article.source` except `image_transcriber.py`, which
branches on `ImageRef.local_path` to decide between disk read and download.

If you find yourself adding a second `if article.source == …` anywhere below the loader,
the abstraction has leaked.

### Authentication flow (Phase 2 only)

All article URLs reached by email are behind the site's login wall. **The system holds no
credentials.** It cannot log in; it can only recognise a login wall, show it to a person,
and wait.

```
1. login.get_authenticated_context()
      → restore state.json and health-check it
      → still valid?  return BrowserContext, nobody is disturbed
      → not valid?    open a VISIBLE browser window, wait for a human to sign in,
                      save the new state.json, return BrowserContext

2. crawler: pre-check on HEALTH_CHECK_URL
      → login.ensure_authenticated(page, HEALTH_CHECK_URL)
      → raise SessionExpiredError only if the login was not completed

3. crawler: for each article URL
      → page.goto(url) → login.ensure_authenticated(page, url)
            ├─ authenticated already        → return True (the common case)
            ├─ not a login wall (404, etc.) → return True, no-op; crawler's guard skips
            └─ login wall → human signs in → RE-NAVIGATE to url → return True
      → extract HTML only after SUCCESS_SELECTOR is confirmed on `url`
      → if ensure_authenticated returns False: skip URL, continue

4. login.ensure_authenticated() is the single point where a login can happen
      → crawler and scheduler never touch the login page
```

Login walls on individual article URLs are resolved **inline**; the scheduler is not
involved. `SessionExpiredError` is raised only when the pre-check login fails, which means
either nobody was there to log in or the wait timed out.

#### Why the human logs in

A scripted username/password fill breaks on anything the site chooses to add — a captcha,
a 2FA code, an email magic link, a consent interstitial, a renamed input — and each break
costs a whole ingestion run and a debugging session. A person at the keyboard handles all
of them, and the system needs to understand exactly one thing about authentication:
`SUCCESS_SELECTOR` is on the page, or it is not. The cost is one sign-in whenever the
session expires; `state.json` makes that rare.

#### The handoff back to the crawler

A completed login almost never leaves the browser on the article — the site lands the
person on a members dashboard or a "welcome back" page. `ensure_authenticated` therefore
**navigates back to the URL the crawler asked for** before returning `True`. Its contract
is one line: *when it returns `True`, the page is at the URL you requested and is
authenticated.* Skip that re-navigation and the crawler files the dashboard's HTML under
the article's URL — wrong content, plausible shape, no error anywhere.

#### Unattended runs

A cron run at 03:00 has nobody to open a window for. `INTERACTIVE_LOGIN` (`auto` |
`always` | `never`; `auto` = "there is a tty") decides whether a human may be asked, and
also whether the browser launches headful. When no human is available and a login is
needed, the run fails immediately with `ManualLoginRequiredError` — it does not wait out
the timeout first — and the message says to run an ingestion from a terminal once to
refresh the session.

Phase 1 touches none of this. A corpus sync runs with no browser, no credentials, and no
network.

> `inbox/SPEC_email_reader.md`.

> `python -c "import importlib.util as u; print(u.find_spec('NAME'))"` from outside the
> repo. `scraper`, `ingestion`, `storage`, `query`, `scheduler`, `logger`, `models`,
> `config` and `app` are all clear.

The markdown corpus itself lives **outside** the repository, at `MD_CORPUS_DIR`. It is
input data, not project source, and is never written to.

## Corpus format reference

```
MD_CORPUS_DIR/                                   # one author, e.g. …/corpus/example-author
├── 2021-05-16-premium-2021-5-16.md
├── 2021-06-27-premium-2021-6-27.md
└── images/
    ├── 2021-05-16-premium-2021-5-16/
    │   └── 00-4c91be07a2.jpg
    └── 2021-06-27-premium-2021-6-27/
        ├── 00-558cf4ffe8.jpg
        └── 01-9f8e7d6c5b.png
```

```markdown
---
title: "Multi-Stock and Sector Update"
subtitle: "June 27, 2021 This report focuses on macro updates, the recent Fed update, …"
author: ""
published: "2021-06-27"
url: "https://www.example.com/premium-2021-6-27"
scraped_at: "2026-08-30T12:18:03+00:00"
cover: "images/2021-06-27-premium-2021-6-27/00-558cf4ffe8.jpg"
truncated: false
word_count: 6951
images_saved: 37
---

Body prose. Tables in GFM pipe syntax are indexed separately.
Images are referenced as ![alt](images/2021-06-27-premium-2021-6-27/01-9f8e7d6c5b.png).
```

- Only top-level `*.md` files are articles; `images/` and its per-article subfolders are
  never scanned for articles, despite carrying article-shaped names
- Each article owns one image subfolder, named `<published>-<url-slug>`. Image paths
  resolve by their **whole relative path** from the article's own folder — never by
  basename, which repeats (`00-*`) in every article and would cross-link two reports
- The cover image is referenced up to three times per file (`cover:` frontmatter,
  `![cover](…)`, `![Premium Feature Image](…)`); the loader dedups by resolved path
- `subtitle`, `scraped_at`, `truncated`, `word_count` and `images_saved` are written by
  the export tool and deliberately not trusted — `images_saved` is compared against the
  images actually resolved as a corpus health check
- `url` is the primary key across the whole system, after `models.canonical_url()` — see
  [SPEC_md_loader.md](ingestion/SPEC_md_loader.md) for the full frontmatter contract
- A file missing `url` still loads, with a synthesised `local:<stem>` id and a WARNING.
  A `local:` id is not a working link — `app.py` renders those source cards as plain text
  rather than dead hyperlinks. Treat every `local:` id in the corpus as a bug in the
  export, not a supported state.

Full parsing rules, fallbacks, and failure behaviour:
[ingestion/SPEC_md_loader.md](ingestion/SPEC_md_loader.md).

## Email format reference

```
From:    author@example.com
Subject: May 2026 Premium Report

Hello,

A new premium report is available in the members area:
https://www.example.com/members/

Here's a direct link to the report:
https://www.example.com/premium-2026-5-10/

- The macro section focuses on...
Best regards, The Author
```

**Extraction rule**: find the phrase `"Here's a direct link to the report:"` and take the
first `https://` URL that follows it (same line or next non-blank line). The members-area
URL appearing before the phrase is ignored. Domain validated against `SITE_DOMAIN`.

## Article identity and overlap between phases

`url` is the single identity key. `metadata_db.get_known_urls()` and
`metadata_db.is_changed(url, hash)` are consulted by both phases, so an article that
somehow arrives twice is skipped the second time rather than duplicated.

In normal operation the two phases do not overlap: the corpus holds the back-catalogue and
email announces genuinely new reports. The dedup path is a safety net, not a workflow —
if it starts firing regularly, the corpus and the email feed have drifted and that is
worth investigating rather than silently absorbing.

`metadata_db.articles.source` records which phase ingested each article, which makes that
check a one-line query.

## Logging standard

Every component follows the contract in [SPEC_logger.md](SPEC_logger.md):

```python
from logger import get_logger
log = get_logger(__name__)   # → "knowledge_repo.<module.path>"
```

- Two outputs: `stderr` (human-readable) + `logs/knowledge_repo.log` (rotating JSON)
- `exc_info=True` on every caught exception
- Credentials, tokens, API keys — **never** logged

Common queries:
```bash
grep '"level": "ERROR"'      logs/knowledge_repo.log | jq .
grep '"level": "CRITICAL"'   logs/knowledge_repo.log | jq .
grep '"trigger": "corpus"'   logs/knowledge_repo.log | jq '{ts,msg,stats}'
grep '"trigger": "email"'    logs/knowledge_repo.log | jq '{ts,msg,email_uid,stats}'
```

`content_hash` has exactly one definition, in `models.py`, called by both producers:

```python
def content_hash(body_text, tables_md, images) -> str:
    """The ONE hash formula. Both md_loader.py and extractor.py call this."""
    parts = [body_text, *tables_md]
    for img in images:                      # already in document order
        if img.local_path is None:          # web image: URL is the only identity
            parts.append(f"{img.src}:")
        else:                               # corpus image: bytes may change in place
            st = Path(img.local_path).stat()
            parts.append(f"{img.src}:{st.st_size}:{st.st_mtime_ns}")
    return sha256("".join(parts).encode()).hexdigest()
```

A web image contributes only its URL, so a re-scrape of unchanged HTML hashes the same. A
corpus image contributes its size and mtime as well, so replacing `chart-01.png` in place
— same filename, new chart — changes the article's hash and forces a re-ingest. Without
that, `is_changed()` returns False, the scheduler skips the article before transcription
runs, and the stale transcription stays in the index forever.

The trailing colon after `img.src` is part of the format for both sources; do not
special-case it away for web images or the two producers will disagree on identical
content. The `.md` file's own path and mtime are never hashed — renaming an article must
not force a re-embed.

Cost note: mtime is not content, so copying the corpus with a tool that does not preserve
mtimes re-embeds everything once. That is the accepted trade against silently stale charts.

`url` is the primary key, so it too has exactly one normal form, in `models.py`, applied
by both producers before the value reaches `metadata_db` or a vector payload:

```python
def canonical_url(raw: str) -> str:
    """The ONE url normal form. Both md_loader.py and extractor.py call this."""
    if not raw:
        return ""
    u = urlsplit(raw.strip())
    scheme = "https"                                  # http and https are one article
    netloc = u.netloc.lower().removeprefix("www.")
    path   = u.path.rstrip("/") or "/"                # trailing slash is not identity
    return urlunsplit((scheme, netloc, path, "", ""))  # query and fragment dropped
```

The corpus writes `https://www.example.com/premium-2021-6-27`; the Phase 2 email link
for the same article typically arrives as
`https://example.com/premium-2021-6-27/?utm_source=newsletter`. Un-normalised, those are
two rows, two sets of vectors, and two citations for one report — and the corpus row is
the one that goes stale, because only the web path gets re-scraped. Dropping the query is
safe for this site (article identity is entirely in the path) and must be revisited
before pointing the pipeline at a site that paginates or versions through query strings.

## Shared exceptions

Most exceptions are private to one module and defined there (`CorpusNotFoundError` in
`md_loader`, `SessionExpiredError` in `crawler`, `ManualLoginRequiredError` in `login`,
`MailboxConnectionError` in `email_reader`, and so on — each module spec lists its own).

Three are raised by more than one module and therefore live in `models.py` so every
module can import them without a cycle:

```python
# models.py — shared exception types

    """The configured embedding model does not match the one recorded on the Qdrant
    collection (or the metadata row). Raised by vector_store, metadata_db, embedder,
    and retriever. Message carries both model names and the re-index instruction."""

class VisionNotSupportedError(ConfigError):
    """VISION_MODEL cannot accept image input. Raised by llm_provider.get_vision_provider()
    at startup."""
```

`ProviderConnectionError`, `ModelNotFoundError` are `llm_provider`'s own (single producer,
listed in [SPEC_llm_provider.md](SPEC_llm_provider.md)); `VectorStoreConnectionError` is
`vector_store`'s. A module spec that names an exception it does not define is pointing at
one of these homes — check there before adding a new class.

### Phase 2 credentials must not be required at import

Every module imports `config`, so a bare `os.environ["LOGIN_URL"]` would make `import
config` raise `KeyError` on a machine that only ever runs Phase 1 — breaking the corpus
sync, the query path, and the whole of build steps 1–12. All Phase 2 secrets therefore use
`os.environ.get(..., "")` and are validated **at point of use**, not at import:

```python
def require_phase2_config() -> None:
    """Raise ConfigError naming every missing or inconsistent Phase 2 setting. Called by
    scraper/login.py and inbox/email_reader.py on entry — never at import time.

    SITE_DOMAIN and HEALTH_CHECK_URL have no default (see config block) because they are
    a cookie target and a network target: an install that fills in LOGIN_URL and
    TRUSTED_SENDER but leaves these blank would fail obscurely — or, if they carried a
    default, health-check the wrong host with a live session. The domain cross-check
    catches the subtler version — everything filled in, but not all for the same site."""
    missing = [n for n in ("LOGIN_URL", "TRUSTED_SENDER", "SITE_DOMAIN", "HEALTH_CHECK_URL")
               if not globals().get(n)]
    if missing:
        raise ConfigError(f"Phase 2 requires these .env settings: {', '.join(missing)}")
    for name in ("LOGIN_URL", "HEALTH_CHECK_URL"):
        if SITE_DOMAIN not in globals()[name]:
            raise ConfigError(f"{name} is not on SITE_DOMAIN ({SITE_DOMAIN}) — "
                              "check every Phase 2 URL points at the same site")

def phase2_configured() -> bool:
    """True when Phase 2 can run. app.py uses this to disable the 'Check email'
    button with a tooltip instead of offering an action that can only fail."""
```

- **Formatting & linting**: `ruff format` + `ruff check` (config in `pyproject.toml`).
  Line length 100. No other formatter. CI fails on a lint or format diff.
- **Types**: annotate every public function signature and dataclass field. `from
  __future__ import annotations` at the top of every module. Type-check is advisory
  (`ruff` only) — no `mypy` gate, but a new `# type: ignore` needs a reason in the same
  line.
- **Naming**: `snake_case` functions and variables, `PascalCase` classes, `UPPER_SNAKE`
  for config constants. Module names are singular nouns (`crawler`, not `crawlers`).
  A function that returns a bool is `is_*` / `has_*`; one that performs I/O and may raise
  is a plain verb (`fetch_pages`, `load_article`).
- **Imports**: stdlib, then third-party, then first-party (`config` / `logger` / `models`
  / sibling modules), each group blank-line separated. `config` is imported for its
  constants by name (`from config import CHUNK_SIZE`), never `import config` then
  `config.CHUNK_SIZE`, except in `require_phase2_config()` where `globals()` is the point.
- **Logging**: `log = get_logger(__name__)` at module top, one line. Structured `extra=`
  dicts, keys from the table in [SPEC_logger.md](SPEC_logger.md). `exc_info=True` on every
  caught exception. Never log a credential, token, cookie, or API key.
- **Errors**: raise a named exception (see *Shared exceptions* and each module spec),
  never a bare `Exception` or `assert` for control flow. A caught-and-swallowed error is
  logged at `WARNING` or above with enough `extra=` to act on it.
- **Docstrings**: one-line summary, then the non-obvious contract (what it returns on the
  empty/miss/skip path, what it never does). Match the surrounding file's density.
- **Comments** explain *why*, not *what*. The specs are full of "without this, X breaks
  silently" rationale — that belongs in the code too, at the line it guards.
- **No new top-level package** without the stdlib-shadow check in *Project directory tree*.

## Testing Strategy

- **Framework**: `pytest` + `pytest-asyncio` (async modules: `login`, `crawler`,
  `image_transcriber`, `monthly_job`). `pytest-cov` for coverage.
- **Location**: `tests/` mirrors the source tree (`tests/ingestion/test_chunker.py`).
  Shared fixtures in `tests/conftest.py`; data in `tests/fixtures/`.
- **Every module spec has a "Testing Notes" section — it is the acceptance-criteria list
  for that module.** A module is not done until every assertion in its Testing Notes is a
  passing test. Do not delete or `xfail` one to land a change; if a test is wrong, fix the
  spec first.
- **The default is a mocked test.** Never call a real LLM API, real mailbox, or real
  website in the suite. `conftest.py` provides `MockTextProvider`, `MockVisionProvider`,
  `MockEmbeddingProvider` (deterministic vectors); patch `llm_provider.get_*_provider`.
- **Levels**:
  - *unit* — pure logic, no services: `models`, `config`, `md_loader`, `chunker`,
    `extractor`, `email_reader` (`.eml` fixtures), `answerer`/`retriever` (mock provider +
    in-memory store). The bulk of the suite.
  - *integration* — `QDRANT_IN_MEMORY=True` and SQLite `:memory:`, still no network:
    `vector_store`, `metadata_db`, and the `monthly_job` corpus path end to end against a
    fixture corpus.
  - *browser* — `pytest-playwright` against a local fixture HTTP server, never the live
    site: `login`, `crawler`. The human is simulated by flipping the fixture's auth flag
    after N polls (see [SPEC_login.md](scraper/SPEC_login.md)).
- **Regression tests that must exist** (each is a silent-failure guard called out in a
  spec): two corpus articles with a colliding `00-*.jpg` basename resolve to different
  files; a renamed `.md` keeps its `content_hash`; a changed image's bytes change it;
  `--reset` does not touch the image cache; `ensure_authenticated` returns the crawler to
  the article URL after the site lands on a dashboard; a dead URL never opens a browser
  window; `canonical_url` collapses the corpus and email spellings of one article.
- **Coverage**: 85% line coverage overall is the CI gate; `models.py`, `md_loader.py`,
  `chunker.py`, `metadata_db.py` are held at 95% (they are pure and cheap, and everything
  downstream trusts them).
- **Determinism**: seed any randomness; monkeypatch the clock for timeout tests so the
  suite never actually waits `MANUAL_LOGIN_TIMEOUT_MS`.

## Boundaries

### Always
- Run `ruff check`, `ruff format --check`, and `pytest` before every commit. CI runs all three.
- Keep a change behind its spec: update the module spec in the same commit as the code,
  and keep the one-`Article` invariant (no module after the loader branches on
  `article.source`, except `image_transcriber` on `ImageRef.local_path`).
- Call the shared helpers — `models.content_hash()`, `models.canonical_url()` — never a
  local reimplementation.
- Route every model call through `llm_provider`; no `anthropic` / `openai` /
  `sentence_transformers` import outside that module.
- `delete_by_url` before `upsert` on every re-ingest. `finish_run` on every exit path.
  `close_browser()` on every Phase 2 exit path.
- Validate and normalise every external string at the boundary: `canonical_url` on every
  URL, `SITE_DOMAIN` dot-boundary check on every email link, `MIN_WORD_COUNT` /
  `MAX_IMAGES_PER_ARTICLE` / `MAX_IMAGE_MB` caps on every article.
- Preserve idempotency: re-running any mode over unchanged content produces only skips.

### Ask first
- Adding a dependency to `requirements.txt`, or a new top-level package.
- Changing a `models.py` dataclass, the SQLite schema, or the Qdrant payload shape
  (all three ripple across every consumer).
- Changing `EMBEDDING_BACKEND` / `LOCAL_EMBEDDING_MODEL` / `EMBEDDING_DIM`, or `CHUNK_SIZE`
  / `CHUNK_OVERLAP` — these invalidate the whole collection and need a full re-index.
- Bumping `PIPELINE_VERSION` (forces a corpus-wide re-ingest — intended, but a cost).
- Changing the vision or answer prompt text.
- Introducing hard deletion of anything, or a code path that clears the image cache.
- CI config, the coverage gate, or a scheduled/cron entry point.

### Never
- Commit `.env`, `session/`, `state.json`, `gmail_token.json`, `data/`, `logs/`, `images/`,
  `debug/`, or any part of the corpus.
- Log a credential, session token, cookie, OAuth token, or API key — including inside a
  traceback or an `extra=` dict.
- Store a website username or password anywhere (env, config, argument, prompt). The human
  signs in, in a visible browser window. `SITE_USERNAME` / `SITE_PASSWORD` do not exist.
- Fill or submit the login form from code; `LOGIN_FORM_SELECTOR` only *recognises* a wall.
- Hard-delete an article row, call `drop_collection()` / `drop_all_articles()` from any
  path other than `--reset`, or wire a "clear and rebuild" into an automated run.
- Delete a failing test, `xfail` it, or weaken an assertion to reach green without saying so.
- Add a second `if article.source == …` below the loader.
- Fetch a URL that failed the `SITE_DOMAIN` check with the session cookies attached.

## Success Criteria

Phase 1 (build steps 1–12) is done when:

- `python scheduler/monthly_job.py --corpus --dry-run` runs clean over the full corpus:
  zero `ERROR` lines, every `WARNING` triaged.
- A full `--corpus` load followed by a second `--corpus` run produces **all skips** and
  zero `vector_store.upsert` calls.
- `python app.py "<a question answerable from one known article>"` returns an answer that
  cites that article's canonical URL, with a retrieval score above `MIN_SCORE_THRESHOLD`.
- `--inspect <url>` on a pilot article passes the gate-3 checklist in
  [SPEC_monthly_job.md](scheduler/SPEC_monthly_job.md).
- `pytest` is green with coverage at or above the gate, on a machine with **no Playwright,
  no mailbox, and no site credentials**.

Phase 2 (build steps 13–17) is done when:

- A notification email from `TRUSTED_SENDER` triggers a run that authenticates (a human
  signs in once), scrapes the linked report, ingests it, and marks the email processed.
- A run interrupted before the ingest completes leaves the email **unread**, and the next
  poll retries it to completion.
- A `--once` run under cron with an expired session fails fast with
  `ManualLoginRequiredError` — no five-minute wait — and leaks no Chromium or node process.
- Switching every backend to Ollama via `config.py` alone (no code change) still answers
  questions.

## Build and run order

### Build order (implement and test in sequence)
1. `models.py`, then `config.py` + `logger.py` — shared foundation; `models.py` first
   because `config.py` imports `ConfigError` from it. Zero external dependencies.
2. `llm_provider.py` — provider abstraction; test with mocks before any real API
3. `storage/metadata_db.py` — SQLite only; test with `:memory:`
4. `storage/vector_store.py` — needs Qdrant: `docker run -p 6333:6333 qdrant/qdrant`
5. `ingestion/md_loader.py` — pure filesystem; test with a fixture corpus
6. `ingestion/chunker.py` — pure text; no services
7. `ingestion/embedder.py` — uses `llm_provider.get_embedding_provider()`
8. `ingestion/image_transcriber.py` — local-file path first, download path second
9. `scheduler/monthly_job.py` — **corpus mode only**; at this point Phase 1 runs end to end
10. `query/retriever.py` — uses `llm_provider.get_embedding_provider()`
11. `query/answerer.py` — uses `llm_provider.get_text_provider()`
12. `app.py` — the system is now queryable against the back-catalogue
13. `inbox/email_reader.py` — test with `.eml` fixtures first; real mailbox last
14. `scraper/login.py` — needs live website
15. `scraper/crawler.py` — needs authenticated session
16. `ingestion/extractor.py` — test with saved `.html` fixtures
17. `scheduler/monthly_job.py` — add email mode; Phase 2 complete

Steps 4–5 of the operational sequence below are a staged first load, not ceremony: one
full pass over the corpus costs real money in vision and embedding calls, and the failures
this pipeline produces are mostly silent. *The controlled first load* in
[SPEC_monthly_job.md](scheduler/SPEC_monthly_job.md) says what each gate is testing and
what to check before spending the rest.

Steps 1–12 deliver a fully working system with no browser, no credentials, and no mailbox.
Phase 2 (13–17) is a strictly additive second milestone — do not start it until you can
ask questions and get cited answers from the corpus.

### First-run sequence (operational)
```bash
# 1. Infrastructure
docker run -d -p 6333:6333 qdrant/qdrant

# 2. Dependencies
pip install -r requirements.txt

# 3. Configure
cp .env.template .env && vi .env      # at minimum: MD_CORPUS_DIR

# 4. Validate the whole corpus — free, no API calls, catches file 217 now

# 5. Pilot two articles end to end: one image-heavy, one structurally odd

# 6. Load the corpus (--reset first only if the pilot ran on code you no longer trust)

# 7. Query
python app.py "What are the author's views on monetary policy?"
streamlit run app.py

# ── Phase 2 setup (only when the corpus pipeline works) ──────────────────────

# 9. Gmail OAuth

python scheduler/monthly_job.py                  # blocking
# or via crontab:
# 0 */12 * * * /path/to/venv/bin/python /path/to/scheduler/monthly_job.py --once
```

### Re-syncing the corpus

Adding or editing markdown files is a supported ongoing operation, not a one-time load:

```bash
python scheduler/monthly_job.py --corpus
```

New files are ingested, files whose `content_hash` changed are re-chunked and re-embedded
(old vectors deleted first), unchanged files are skipped.

Deleting a `.md` file does **not** remove it from the index — a sync that removed articles
because a file looked absent would wipe the database the first time someone ran it against
the wrong folder. Reconciliation is a separate, explicit command:

```bash
python scheduler/monthly_job.py --prune --dry-run   # list corpus articles with no file
python scheduler/monthly_job.py --prune             # archive them
```

`--prune` archives rather than deletes: it drops the article's vectors so it stops being
retrieved, and keeps its metadata row with `status = 'archived'`. Nothing in this system
hard-deletes an article. Restore the file, run `--corpus`, and the article comes back.
See [scheduler/SPEC_monthly_job.md](scheduler/SPEC_monthly_job.md).
