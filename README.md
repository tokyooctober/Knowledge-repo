# Knowledge Repository

A personal RAG system that answers natural-language questions about one author's premium
articles, with inline citations generated by an LLM.

The vector database is populated from **two content sources** that converge on a single
`Article` object and share one ingestion pipeline (transcribe images → chunk → embed →
store). Both are idempotent — re-running either with unchanged content produces only skips,
never duplicate vectors.

| | Phase 1 — Corpus | Phase 2 — Email |
|---|---|---|
| **What** | The back-catalogue, exported as markdown + images | Each new report as it is published |
| **Source** | A local folder (`MD_CORPUS_DIR`) | A notification email with a direct link |
| **Acquisition** | `ingestion/md_loader.py` — read files from disk | `email_reader` → `login` → `crawler` → `extractor` |
| **Cadence** | Re-runnable sync; run whenever files change | Scheduler / 12h poll |
| **Auth** | None | Human-in-the-loop Playwright login (paywall) |

Both phases are implemented and tested. See [`SPEC.md`](SPEC.md) for the full architecture
and [`TASKS.md`](TASKS.md) for the build log.

## Tech stack

| Area | Choice |
|---|---|
| **Language** | Python 3.11+ |
| **Vector store** | [Qdrant](https://qdrant.tech/) (`qdrant-client`); in-memory mode for tests |
| **Metadata / cache** | SQLite (WAL mode) — article metadata, image-transcription cache |
| **Embeddings** | `sentence-transformers` (local, default: `BAAI/bge-large-en-v1.5`) or any OpenAI-compatible endpoint |
| **Text + vision LLM** | Provider abstraction over Anthropic, OpenAI, and OpenAI-compatible backends (`llm_provider.py`) |
| **Chunking** | `langchain-text-splitters` + `tiktoken` (512-token body chunks; tables and image transcriptions chunked whole) |
| **HTML extraction** | `trafilatura` (body), `pandas` + `beautifulsoup4` (tables), `lxml` |
| **Scraping / auth** | `playwright` (Chromium), human-in-the-loop login, persisted `state.json` session |
| **Email** | Gmail API (`google-api-python-client`) or IMAP; trusted-sender + subject filtering |
| **Scheduling** | `apscheduler` (`BlockingScheduler`) or one-shot `--once` for OS cron |
| **UI** | Streamlit app + CLI (`app.py`) |
| **Config** | `python-dotenv` — all secrets in `.env`, never committed |
| **Logging** | Structured JSON logs (`logger.py`); credentials and tokens are never logged |
| **Retries** | `tenacity` (rate-limit backoff) |
| **Tooling** | `ruff` (format + lint, line length 100), `pytest` + `pytest-asyncio` + `pytest-cov` + `pytest-timeout` |
| **Tests** | ~360 tests, 96%+ line coverage (CI gate: 85% overall, 95% for the pure core) |

## Layout

```
app.py            CLI + Streamlit UI
config.py         every constant; Phase-2 validators
logger.py         structured JSON logger
llm_provider.py   Text / Vision / Embedding provider protocols + backends
models.py         shared dataclasses + content_hash() / canonical_url()

inbox/            email_reader.py       — Phase 2 trigger: trusted email → URL
scraper/          login.py, crawler.py  — Phase 2 auth + paywall fetch
ingestion/        md_loader.py, extractor.py, image_transcriber.py,
                  chunker.py, embedder.py
storage/          vector_store.py (Qdrant), metadata_db.py (SQLite)
query/            retriever.py, answerer.py
scheduler/        monthly_job.py        — corpus sync + email scheduler entrypoint
tests/            pytest suite, mirrors the source tree
```

Runtime data (`data/`, `logs/`, `images/`, `session/`) and the markdown corpus itself live
outside version control.

## Setup

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium                        # Phase 2 only

cp .env.template .env                              # then fill it in
```

Phase 1 needs only `MD_CORPUS_DIR`, `AUTHOR_NAME`, and an LLM/embedding backend. Phase 2
additionally needs `LOGIN_URL`, `HEALTH_CHECK_URL`, `SITE_DOMAIN`, and `TRUSTED_SENDER`
(plus mailbox credentials). The system holds **no site credentials** — when a login is
needed it opens a visible browser window and waits for you to sign in.

Qdrant: run `docker run -p 6333:6333 qdrant/qdrant`, or set `QDRANT_IN_MEMORY=True` for
local use without Docker.

## Usage

```bash
# Phase 1 — sync the markdown corpus (re-runnable; new + changed files only)
python scheduler/monthly_job.py --corpus
python scheduler/monthly_job.py --corpus --dry-run           # report, write nothing
python scheduler/monthly_job.py --corpus --dir /path/to/md   # override MD_CORPUS_DIR

# Phase 2 — email-triggered updates
python scheduler/monthly_job.py            # blocking scheduler (APScheduler)
python scheduler/monthly_job.py --once     # single check, then exit (for OS cron)

# Query
streamlit run app.py
python app.py "What are the author's views on monetary policy?"
python app.py "..." --json
```

## Roadmap

The system today does dense retrieval over chunks. The next three steps move it toward a
structured, self-hosted knowledge base:

1. **Entity resolution** — extract people, institutions, assets, and concepts from every
   article and resolve mentions to canonical entities (e.g. "the Fed", "Federal Reserve",
   "FOMC" → one node). Deduplicate across the corpus and across new email-ingested reports.

2. **Knowledge graph** — build a graph of the resolved entities and their relationships
   over time, so queries can traverse connections ("what has the author said about X's
   effect on Y?") rather than relying on chunk similarity alone. Retrieval becomes a hybrid
   of vector search and graph walks.

3. **Local LLM** — move text generation and vision transcription onto a locally hosted
   model (via the existing `openai_compat` backend — Ollama / vLLM), so the whole pipeline,
   including entity extraction and answer synthesis, runs without a third-party API. The
   provider abstraction in `llm_provider.py` already isolates this change to configuration.
